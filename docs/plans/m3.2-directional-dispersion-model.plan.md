# M3.2 — Directional dispersion model

GitHub issue: [#27](https://github.com/andywrussell/caddai/issues/27)

## Goal

Introduce `caddai.statistics.DirectionalDispersion`, representing lateral
shot spread and systematic bias, alongside the existing `CarryDistribution`
in the `statistics` leaf subsystem. Adopt permanently the lateral-offset
sign convention (negative left, zero on-line, positive right of the
intended target line, independent of handedness). This task is independent
of M3.1 and blocks M3.3 (#28).

## Architect input

CaddAI Architect reviewed the design: **no ADR required**. `statistics` is
already a named leaf subsystem in `AGENTS.md` §3/§4, owned by the Player
Engineer — this adds a second model class to an already-planned subsystem,
not a new dependency, public API change, unit change, or ownership change.
The sign convention is architecturally sound and already pre-committed
verbatim in `docs/roadmap.md`'s M3 entry — this issue executes an
already-agreed decision. Guidance:

- Keep `DirectionalDispersion` as its own model in
  `src/caddai/statistics/models.py` (not merged into `CarryDistribution`) —
  matches the roadmap's framing of carry distribution + directional
  dispersion as distinct statistical facets, and keeps M3.3's later
  composition clean.
- `lateral_bias_metres` is signed with no natural bound — don't add an
  artificial range constraint.
- Document the sign convention in two places: the model/module docstring
  (canonical, load-bearing) and `docs/player-model.md`'s "Directional
  dispersion" bullet.
- No handedness field or normalization logic belongs in `statistics` — that
  would reintroduce a branch this convention is designed to avoid.
- Extend the existing `statistics` `SubsystemBoundary` entry in
  `tests/test_architecture_boundaries.py`; no new entry needed.

## Tasks

### Task 1 — `DirectionalDispersion` model

- Owning engineer: Player Engineer
- Files: `src/caddai/statistics/models.py`, `src/caddai/statistics/__init__.py`
- Acceptance criteria:
  - `DirectionalDispersion` Pydantic model: `lateral_stddev_metres: float`
    (`ge=0`), `lateral_bias_metres: float` (signed, unconstrained).
  - Docstring states the sign convention: negative = left of the intended
    target line, zero = on-line, positive = right, independent of
    handedness.
  - Re-exported from `caddai.statistics.__init__`.
  - `caddai.statistics` continues to import nothing from other `caddai.*`
    modules (leaf subsystem preserved).
- Test expectations (QA Engineer):
  - Valid construction with a typical positive, negative, and zero
    `lateral_bias_metres` succeeds.
  - `lateral_stddev_metres` accepts zero (no measured spread yet) and a
    typical positive value.
  - `lateral_stddev_metres < 0` raises a validation error.

### Task 2 — Architecture boundary coverage

- Owning engineer: Player Engineer (same PR)
- Files: `tests/test_architecture_boundaries.py`
- Acceptance criteria:

    coverage still exercises `models.py` (no new file added, so likely no
    change needed beyond confirming coverage — only touch if a new source
    file is introduced).

### Task 3 — Documentation update

- Owning engineer: Player Engineer
- Files: `docs/player-model.md`
- Acceptance criteria:

    now exists.
