## Architect input

The CaddAI Architect reviewed this issue (read-only) and confirmed:

- **No ADR required.** The finalized GeoJSON schema (Point + single-
  exterior-ring Polygon) is already the schema ADR 0003 introduced; this
  issue only documents existing, already-ADR'd decisions.
- **`docs/roadmap.md`'s M2 entry is stale**: it still claims "the `course`
  subsystem and GeoJSON parsing are not yet implemented." Mark M2
  `*(complete)*` (matching M0/M1's style) and rewrite the body as a short
  summary linking to `docs/course-engine.md` and ADRs 0002–0004, rather
  than re-describing the schema (per docs.instructions.md's "don't
  duplicate — link instead").
- **`docs/architecture.md`'s status banner is stale** (and was already
  stale before M2 — it says "only the bootstrap package... exists", false
  since M1 added `player`/`strategy`). Correct it to state current
  implementation status (`gps`/`course` complete per M2; a minimal
  `player`/`strategy` vertical slice from M1; `statistics`/`simulation`/
  `llm`/`api`/`cli` don't exist yet) and drop "(planned)" from the
  "Subsystems" heading, without re-describing per-subsystem detail that
  belongs in `course-engine.md`/`player-model.md`/`strategy-engine.md`.
- **`docs/backlog.md`**: remove the now-completed candidate item "Define
  the GeoJSON `properties` schema for course features (feeds M2)."
- **`docs/course-engine.md`**: status banner and "Distance-to-feature
  queries" section are already accurate; add a new `## Known limitations`
  section (before `## Units`) consolidating the four **permanent** M2.5
  design limitations, currently scattered as prose:
  1. No pin/flag position concept (`Hole.pin_position` doesn't exist;
     "centre" = green polygon centroid).
  2. Convex/simple-polygon assumption for front/back/carry (nearest/
     farthest-crossing simplification) — combined with (4) below into one
     bullet, since they're the same root limitation.
  3. No interior rings/holes in a boundary polygon (ADR 0003 explicit
     non-goal).
  4. No concave multi-crossing support (same root cause as #2 — one
     combined bullet, not two).
  Trim the now-redundant inline restatements elsewhere in the doc to a
  one-line pointer to this new section.
- **Test-coverage gaps go to `docs/backlog.md`, not `course-engine.md`**:
  the two remaining M2.5 items (missing regression coverage for a
  line-of-play exactly overlapping a polygon edge; missing regression
  coverage directly targeting the `1e-6` m Shapely precision-snap
  boundary) are process/QA debt, not permanent product limitations — add
  as two new candidate items under `docs/backlog.md`'s "Candidate items".
  Both were already flagged non-blocking by the Adversarial Reviewer
  during M2.5's review; writing the tests now would be new
  test/production-adjacent work under a documentation-only issue,
  contrary to the explicit "no new product functionality" instruction.
- No other stale `course`/`gps` references found in `AGENTS.md` (its §3
  dependency table is explicitly forward-looking "planned subsystems"
  language, not a false current-state claim — no change needed there).
- `CHANGELOG.md`: add one small `### Changed` entry for this
  documentation-consolidation issue itself (M2.6, issue #8), satisfying
  the issue's own "CHANGELOG.md reflects the M2 change" acceptance
  criterion for *this* change specifically (M2.1–M2.5's own entries
  already exist from their respective issues).
