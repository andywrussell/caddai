# M3.x — Enforce finite values in statistical domain models

GitHub issue: [#38](https://github.com/andywrussell/caddai/issues/38)

## Goal

Ensure `caddai.statistics` domain models (`CarryDistribution`,
`DirectionalDispersion`) reject NaN and positive/negative infinity before
those values can reach later `simulation`/`strategy` code. This must land
before M4 Monte Carlo simulation begins (#38 blocks #10).

## Architect input

CaddAI Architect reviewed the design: **no ADR required**. This is a
validation-tightening change to an already-planned leaf domain module, not a
new dependency, public API contract change, canonical unit change, module
ownership change, or dependency-direction change. The proposed
`field_validator`-based finiteness check is architecturally sound, keeps
`caddai.statistics` a leaf module (no new `caddai.*` imports), and stays
inside the existing `player → statistics` dependency edge.

Flagged (non-blocking) risks for this change:

- `inf`/`nan` gaps also exist in `player/models.py` (`Club.name` length
  aside, `ShotRecord.achieved_carry_metres`/`lateral_offset_metres`) — **out
  of scope** for this issue per its explicit scope (`statistics/models.py`
  only); note as a backlog follow-up, not silently fixed here.
- Prefer a single `field_validator` covering both fields per model over
  duplicated per-field validators.
- The nested-`Club`-validation test belongs in `tests/test_player_models.py`
  (black-box test of pydantic's normal nested-model propagation), not
  `tests/test_statistics_models.py`.

## Tasks

### Task 1 — Finite-value validators on `CarryDistribution` / `DirectionalDispersion`

- Owning engineer: Player Engineer
- Files: `src/caddai/statistics/models.py`
- Acceptance criteria:
  - `CarryDistribution.mean_metres` rejects NaN, `+inf`, `-inf` (currently
    `+inf` incorrectly passes `gt=0` since `inf > 0` is `True`); stays `gt=0`
    for finite values.
  - `CarryDistribution.stddev_metres` rejects NaN, `+inf`, `-inf`; stays
    `ge=0` for finite values.
  - `DirectionalDispersion.lateral_stddev_metres` rejects NaN, `+inf`,
    `-inf`; stays `ge=0` for finite values.
  - `DirectionalDispersion.lateral_bias_metres` rejects NaN, `+inf`, `-inf`;
    stays unconstrained in sign for finite values.
  - No change to field names, types, or existing constraints for valid
    finite input — all current passing tests in
    `tests/test_statistics_models.py` continue to pass unchanged.
  - No changes to `src/caddai/strategy/` or `src/caddai/simulation/`.
- Test expectations (QA Engineer):
  - Parametrized NaN / `+inf` / `-inf` rejection tests for each of the four
    fields in `tests/test_statistics_models.py`.
  - Existing valid-value and negative-value tests remain green with no
    edits needed beyond what NaN/inf coverage adds.
  - A new test in `tests/test_player_models.py` constructing a `Club` via
    dict input with a non-finite nested `carry_distribution` (and
    separately `dispersion`) field value, asserting `ValidationError` is
    raised — covers nested validation propagation through `Club`.
