# M4.7 — Environment/physics transformation layer and simulation bootstrap

GitHub issue: [#55](https://github.com/andywrussell/caddai/issues/55)

## Goal

Bootstrap the `caddai.simulation` subsystem with a deterministic
environment/physics transform: wind, elevation, and (optional) air-density
effects applied to a forward-modelled shot outcome, kept fully separate
from `PlayerShotDistribution`'s intrinsic golfer-variability parameters.
No stochastic sampling (M4.8), no course-relative mapping, no
rollout/terrain, no strategy/EV logic.

## Architect input

CaddAI Architect reviewed issue #55 and produced a binding design (see
full text in session record; summarised below):

- **Module layout**: `src/caddai/simulation/{__init__.py,models.py,
  environment_config.py,environment.py}`.
- **Models** (`models.py`): `WindComponents` (signed
  `longitudinal_mps` — positive=tailwind/negative=headwind — and
  `lateral_mps` — positive=rightward effect/negative=leftward, matching
  the existing `DirectionalDispersion`/`ShotRecord` lateral convention),
  `EnvironmentInput` (wraps `WindComponents`,
  `elevation_delta_metres` signed positive=uphill/negative=downhill,
  optional `air_density_kg_per_m3`), `ShotOutcome` (single type used for
  both intrinsic and transformed outcomes —
  `downrange_metres`/`lateral_metres`, signed, never clamped). All frozen
  Pydantic models, all fields finite-validated.
- **Config** (`environment_config.py`): `EnvironmentTransformConfig`
  (frozen, versioned `config_version` default
  `"m4.7-provisional-v1"`), `DEFAULT_ENVIRONMENT_TRANSFORM_CONFIG`, holding
  every provisional coefficient (tailwind/headwind/crosswind sensitivity,
  elevation sensitivity, air-density sensitivity, reference carry,
  reference air density, club-category sensitivity multipliers) with
  explicit evidence-classification docstrings (physics-derived vs.
  evidence-informed-provisional vs. arbitrary-provisional). None described
  as "calibrated".
- **Transform** (`environment.py`):
  `apply_environment_transform(outcome, environment, *, club_category=None,
  config=DEFAULT_ENVIRONMENT_TRANSFORM_CONFIG) -> ShotOutcome`.
  - Wind scale factor = `max(outcome.downrange_metres, 0.0) /
    reference_carry_metres` (hang-time proxy, floored at zero so an
    already-negative intrinsic outcome cannot invert wind's sign).
  - Headwind/tailwind: **asymmetric**, distinct linear coefficients
    (`headwind_sensitivity_metres_per_mps` >
    `tailwind_sensitivity_metres_per_mps`) — explicitly not claiming
    `+5 tailwind == -(-5 headwind)`; documented rationale (headwind
    increases relative airspeed/induced lift disproportionately).
  - Crosswind: linear, symmetric, sign-consistent with `lateral_mps`.
  - Elevation: `-elevation_delta_metres * elevation_sensitivity`,
    club/carry-independent (deliberate simplification).
  - Air density: skipped when `None`; otherwise linear correction via
    `reference_air_density / actual - 1.0`, using raw (unfloored)
    downrange.
  - Club-category multiplier applies only to wind terms; `None`/`OTHER`
    → `1.0`; `PUTTER` → raises
    `EnvironmentTransformUnsupportedClubCategoryError` before any table
    lookup (putting has no airborne aerodynamic regime to model; consistent
    with `ClubCategorySupportStatus.DEFERRED` stance elsewhere, but this is
    a local error type — no reuse of
    `PopulationPriorUnsupportedCategoryError`).
  - Reference/zero environment (`EnvironmentInput()`) is an exact identity
    transform (every additive term evaluates to `0.0`).
  - Signed downrange: never clamped, never rejected — negative transformed
    downrange is a valid signed coordinate (consistent with M4.4's
    `ShotRecord.final_downrange_metres` precedent).
  - No RNG/NumPy-random anywhere in this module.
- **Dependency boundary**: new `SubsystemBoundary` entry, name
  `"simulation"`, `allowed_caddai_prefixes=("caddai.simulation",
  "caddai.statistics")` only. `ClubCategory` imported from
  `caddai.statistics.models`. No import of
  `caddai.strategy.models.Wind`/`LieType`, `caddai.player`,
  `caddai.course`, or any adapter/UI package.
- **ADR**: none required — no new dependency, no public-API-contract
  change to existing types, no canonical-unit change, no ownership change,
  no dependency-direction violation (simulation→statistics is within the
  approved inward direction), deterministic-strategy and offline-first
  principles unaffected. Confirmed by the Architect.

## Tasks

### Task 1 — `caddai.simulation` bootstrap + environment transform (Strategy Engineer)

- Files: `src/caddai/simulation/__init__.py`,
  `src/caddai/simulation/models.py`,
  `src/caddai/simulation/environment_config.py`,
  `src/caddai/simulation/environment.py`.
- Acceptance criteria: matches Architect design above exactly (model
  fields/constraints, transform formulas/signature, config fields/version,
  PUTTER rejection, identity-at-reference, no silent clamping, finite
  validation throughout, no RNG).
- Update `tests/test_architecture_boundaries.py` with the new
  `SubsystemBoundary` entry for `simulation`.

### Task 2 — Tests (QA Engineer, informs/accompanies Task 1)

New `tests/test_simulation_environment.py` covering (minimum, from issue
acceptance criteria + Architect design):

- Reference/zero environment ⇒ exact identity transform.
- Headwind reduces downrange; stronger headwind has larger effect.
- Tailwind increases downrange; stronger tailwind has larger effect.
- Headwind/tailwind asymmetry is observable (`+N` tailwind effect
  magnitude ≠ `-N` headwind effect magnitude) — asserts the documented
  non-symmetry explicitly, not accidentally.
- Left/right crosswind signs correct; stronger crosswind ⇒ larger lateral
  shift; zero crosswind ⇒ lateral outcome unchanged.
- Uphill (`elevation_delta_metres > 0`) reduces downrange; downhill
  increases it.
- Air density: `None` ⇒ no effect; below-reference density increases
  downrange; above-reference decreases it.
- Club-category sensitivity: different categories give different
  magnitudes for the same wind input; `None`/`OTHER` behave identically;
  `PUTTER` raises `EnvironmentTransformUnsupportedClubCategoryError`.
- Determinism: repeated calls with identical inputs produce identical
  output.
- Immutability: input `ShotOutcome`/`EnvironmentInput` objects unchanged
  after the call (frozen models — construction-level guarantee, assert via
  before/after field equality).
- Finite-value validation: non-finite wind/elevation/air-density/outcome
  inputs rejected at construction (`ValidationError`).
- Config validation/versioning: `EnvironmentTransformConfig` exposes
  `config_version`; invalid coefficient values rejected where bounded.
- Negative transformed downrange is preserved, not clamped.
- Architecture boundary: covered by
  `tests/test_architecture_boundaries.py`'s new `simulation` entry
  (parametrized, no separate test file needed for this part).

## Parallelism

Single-subsystem change (`caddai.simulation` + one architecture-boundary
test file edit) — Task 1 and Task 2 are sequenced (implementation then/with
tests) rather than parallelised across engineers, to avoid two agents
editing overlapping new files simultaneously. Strategy Engineer implements
both production code and, given QA Engineer's test list, the test file.

## Addendum 1 — signed-downrange wind-exposure validity domain

Before finalising the PR, a review question was raised: whether the
wind-exposure "hang-time" proxy (`scale`, floored at `max(downrange, 0.0)`)
could sign-invert wind's effect for a non-positive intrinsic
`downrange_metres`. Architect review confirmed no bug exists (the floor
already prevents this) and decided (option B of the choices offered): keep
the floor-at-zero behaviour, and document it explicitly as a deliberate V1
validity-domain restriction — all wind effects are exactly zero (not
inverted, not silently wrong) for non-positive intrinsic downrange. No
formula change. Added: docstring clarifications in `environment.py`/
`environment_config.py`, flagged for M4.8; six new tests in
`tests/test_simulation_environment.py` proving direction is governed
solely by wind sign across positive/zero/negative downrange cases. No ADR.

## Addendum 2 — policy-neutral optional environment transform

A further product/architecture requirement: environmental assistance must
be optional at the caller level (future casual-vs-competition round
modes), without `caddai.simulation` containing any Rules-of-Golf/
competition-mode policy. Architect review decided: **zero production
behaviour/signature change** — a caller already disables environmental
adjustment simply by not calling `apply_environment_transform` (the
intrinsic `ShotOutcome` is used unchanged), and each individual
environmental feature (wind/elevation/air density) is already
independently neutralisable via `EnvironmentInput`'s existing per-field
defaults. No `environment_enabled`/`competition_mode`/`rules_mode` flag was
added, and none should be. Added: explicit ENVIRONMENT ENABLED/DISABLED
pipeline documentation for the M4.8 implementer in `environment.py`'s
module/function docstrings and `__init__.py`'s module docstring; a
policy-neutrality non-goal bullet in `docs/strategy-engine.md`; a
regression test (`tests/test_architecture_boundaries.py::
test_simulation_contains_no_rules_of_golf_policy_identifiers`) guarding
against a future competition/rules-mode flag being added to
`caddai.simulation`. Recorded a future pre-mobile-MVP Rules-of-Golf/
competition-conformance review requirement in `docs/roadmap.md`'s M5.5
entry (planning/documentation only). No ADR.
