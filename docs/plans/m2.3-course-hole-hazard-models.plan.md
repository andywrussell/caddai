# M2.3 — Course/hole/hazard domain models

GitHub issue: [#5](https://github.com/andywrussell/caddai/issues/5)

## Goal

Add Pydantic v2 domain models for `Course`, `Hole` (par + ordered features),
and a `FeatureType` enum covering tee/fairway/green/bunker/water/OB/landing
area, in a new `caddai.course` subsystem, owned by the Course Engineer.

## Architect input

The CaddAI Architect reviewed this issue (read-only) and recommended:

- New package: `src/caddai/course/` with `__init__.py` + `models.py`,
  mirroring the existing `gps/models.py` / `player/models.py` precedent.
  GeoJSON parsing remains separate, not-yet-implemented, out of scope here.
- `course` may depend on `caddai.gps` (specifically
  `caddai.gps.models.Coordinate`) for feature positions. This is consistent
  with the `COURSE --> GPS` edge in `docs/architecture.md`'s system diagram
  and with `AGENTS.md` §4 assigning both `course/` and `gps/` to the Course
  Engineer. The "siblings: neither depends on the other" note describes the
  two subsystem *pairs* (`course`/`gps` vs. `player`/`statistics`) as
  independent of each other, not a prohibition on `course → gps` within the
  pair.
- Shapely is **not** required for this issue. ADR 0002 reserves Shapely for
  actual geometry operations (polygons, hazards, containment/carry
  queries); the stated acceptance criteria only need Pydantic validation
  and a constructible fixture, satisfied by point positions
  (`Coordinate`). Polygon-backed feature geometry is deferred to a later,
  separately-scoped task.
- Enum name: `FeatureType` (not `HazardType`, since tee/fairway/green/
  landing-area are not hazards), values `TEE`, `FAIRWAY`, `GREEN`,
  `BUNKER`, `WATER`, `OUT_OF_BOUNDS`, `LANDING_AREA`, implemented as
  `StrEnum` per the `caddai.strategy.models` precedent.
- No new ADR required; ADR 0002 already covers the Shapely-deferral
  rationale.
- `Hole.features` should be `list[Feature]` (plain list preserves order);
  the Course Engineer/QA Engineer should decide deliberately whether
  `features` requires `min_length=1` (a hole always has at least a tee and
  green in reality) even though the issue's acceptance criteria don't
  explicitly require it. Decision: require `min_length=1` for domain
  correctness and consistency with `Player.clubs`.
- Non-blocking doc note: `AGENTS.md` §3's `course` "Depends on" table cell
  says "domain types only" but omits `gps`, while the diagram shows the
  edge — worth a one-line correction in this PR's docs pass.

## Tasks

1. **Course Engineer** — implement `src/caddai/course/` (owned subsystem,
   files: `__init__.py`, `models.py`).
   - `FeatureType(StrEnum)`: `TEE`, `FAIRWAY`, `GREEN`, `BUNKER`, `WATER`,
     `OUT_OF_BOUNDS`, `LANDING_AREA`.
   - `Feature(BaseModel)`: `feature_type: FeatureType`,
     `position: Coordinate` (from `caddai.gps.models`).
   - `Hole(BaseModel)`: `number: int` (`gt=0`), `par: int` (`gt=0`),
     `features: list[Feature]` (`min_length=1`).
   - `Course(BaseModel)`: `name: str` (`min_length=1`),
     `holes: list[Hole]` (`min_length=1`).
   - Full strict type hints (mypy strict); concise docstrings per
     `.github/instructions/python.instructions.md`.
   - No imports from `player`, `strategy`, `statistics`, `simulation`,
     `llm`, `api`, or `cli`.
   - Update `docs/course-engine.md` status note (mirroring how
     `gps`'s "now implemented" note reads) once implemented, and correct
     the `AGENTS.md` §3 `course` dependency cell to include `gps`.
   - Acceptance criteria (from issue #5):
     - Models validate required fields (positive `par`, non-empty
       `holes` list).
     - A 2-hole fixture course constructs successfully in a test.
     - Full strict type hints.
     - No imports from `player`, `strategy`, or `simulation`.

2. **QA Engineer** — write `tests/test_course_models.py` covering:
   - Valid construction of `FeatureType`, `Feature`, `Hole`, `Course`.
   - A 2-hole fixture course (each hole with tee/fairway/green features)
     constructs successfully.
   - `Hole` rejects `par <= 0` (zero and negative).
   - `Hole` rejects an empty `features` list.
   - `Course` rejects an empty `holes` list.
   - Add a `course` entry to `tests/test_architecture_boundaries.py`'s
     `SUBSYSTEM_BOUNDARIES`, allowing only `caddai.course` and
     `caddai.gps` prefixes, to statically enforce the dependency rule.

## Parallelism

Single subsystem, single owner (Course Engineer) — no parallel engineer
tasks for this issue. QA Engineer test design proceeds alongside/ahead of
implementation, both on the same feature branch.

## Escalations

None. No new dependency, no public API/contract change, no canonical-unit
change, no ownership change, no dependency-direction change.
