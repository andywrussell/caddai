# M3.x — Reject non-finite `ShotRecord` measurements

GitHub issue: [#43](https://github.com/andywrussell/caddai/issues/43)
(sub-issue of the M3 parent, [#9](https://github.com/andywrussell/caddai/issues/9))

## Goal

Ensure `ShotRecord.achieved_carry_metres` and `ShotRecord.lateral_offset_metres`
in `src/caddai/player/models.py` reject NaN and positive/negative infinity,
closing the follow-up explicitly flagged (but scoped out) by issue #38
("M3.x — Enforce finite values in statistical domain models").

## Architect input

CaddAI Architect reviewed the design: **no ADR required**. This is a
validation-tightening change to an already-owned domain model
(`caddai.player`), not a new dependency, public API contract change,
canonical unit change, module ownership change, or dependency-direction
change. Neither `AGENTS.md` §2.1 (deterministic strategy) nor §2.2
(offline-first active round) is touched.

Findings:

- A single `field_validator("achieved_carry_metres", "lateral_offset_metres")`
  on `ShotRecord`, mirroring the pattern in `caddai/statistics/models.py`
  (#38/PR #42), is architecturally sound.
- Reusing `caddai.statistics.models._require_finite` directly would mean
  importing a private (underscore-prefixed) name across a module boundary —
  avoid this. Duplicate the small `math.isfinite` helper locally in
  `player/models.py` instead, matching how `statistics/models.py` defines
  its own copy in isolation. This keeps the existing `player → statistics`
  dependency edge unchanged (no new import surface).
- `achieved_carry_metres` keeps its existing `ge=0` constraint for finite
  values (`0.0` stays valid); `lateral_offset_metres` stays unconstrained in
  sign for finite values — no behavioural change for currently-valid finite
  inputs.
- No changes to `Club`, `Player`, `CarryDistribution`, or
  `DirectionalDispersion`.
