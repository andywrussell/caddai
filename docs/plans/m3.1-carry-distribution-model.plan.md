# M3.1 — Carry distribution model

GitHub issue: [#26](https://github.com/andywrussell/caddai/issues/26)

## Goal

Introduce `caddai.statistics.CarryDistribution`, a parametric statistical
model of carry distance (mean + variability, metres), as the first primitive
of the new `statistics` leaf subsystem. This is the first M3 task and has no
dependencies; it blocks M3.3 (#28).

## Architect input

CaddAI Architect reviewed the design: **no ADR required**. `statistics` is
already a named leaf subsystem in `AGENTS.md` §4 and `docs/architecture.md`'s
dependency table, owned by the Player Engineer — this is implementing
already-planned architecture, not a new dependency, public API change, or
unit change. Boundary shape (`allowed_caddai_prefixes=("caddai.statistics",)`)
correctly mirrors the existing `caddai.gps` leaf-subsystem pattern. Note for
later: M3.3 (#28) will need to reconcile `Club.expected_carry_metres` with
`CarryDistribution.mean_metres` — no action needed now.

## Tasks

### Task 1 — `CarryDistribution` model

- Owning engineer: Player Engineer
- Files: `src/caddai/statistics/__init__.py`, `src/caddai/statistics/models.py`
- Acceptance criteria:
  - `CarryDistribution` Pydantic model with `mean_metres: float` (`gt=0`) and
    `stddev_metres: float` (`ge=0`).
  - Module docstring references `docs/player-model.md`.
  - `caddai.statistics` imports nothing from other `caddai.*` modules.
- Test expectations (QA Engineer):
  - Valid construction with typical values succeeds.
  - `mean_metres <= 0` (zero and negative) raises a validation error.
  - `stddev_metres < 0` raises a validation error; `stddev_metres == 0` is
    valid (a club with no measured variability yet).

### Task 2 — Architecture boundary coverage

- Owning engineer: Player Engineer (same PR, small/clearly-scoped shared test
  file addition)
- Files: `tests/test_architecture_boundaries.py`
- Acceptance criteria:
  - New `SubsystemBoundary` entry for `statistics`
    (`allowed_caddai_prefixes=("caddai.statistics",)`), covering the new
    source files, following the existing `gps` leaf-subsystem pattern.

### Task 3 — Documentation status update

- Owning engineer: Player Engineer
- Files: `docs/player-model.md`
- Acceptance criteria:
  - Status note updated to reflect that `src/caddai/statistics/` now exists
    with `CarryDistribution`, distinct from the still-planned dispersion/
    performance-history/round-statistics pieces.

## Parallelism

All tasks touch a small, non-overlapping set of new/shared files and are
implemented together by the Player Engineer in one pass (no parallel
delegation needed for a task this size).
