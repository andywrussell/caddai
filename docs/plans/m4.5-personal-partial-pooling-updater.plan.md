# M4.5 — Personal partial-pooling player-model updater

GitHub issue: [#53](https://github.com/andywrussell/caddai/issues/53)
(parent [#10](https://github.com/andywrussell/caddai/issues/10), M4).
Depends on M4.1 (#49), M4.3 (#51), M4.4 (#52) — all merged into `main`.
Blocks M4.6 (#54).

## Goal

Implement CaddAI's first personal-learning mechanism: a deterministic,
closed-form partial-pooling (empirical-Bayes-style shrinkage) update that
moves a golfer's `PlayerShotDistribution` from its current (population-prior
or cold-start-onboarding) value toward personal `ShotRecord` evidence, at a
per-parameter rate consistent with the M4.0 research ordering (location
fastest, dispersion slower, correlation slower still, degrees-of-freedom not
learned at all in V1).

## Architect input (full review on file)

The CaddAI Architect subagent reviewed this issue read-only before
implementation began. Full review preserved verbatim in this plan's
"Architect decision record" section below. Summary of binding decisions:

1. **Module split**: pure shrinkage math in a new
   `src/caddai/statistics/personalisation.py` (leaf module, no
   `caddai.player` import); `ShotRecord` → arrays glue in a new
   `src/caddai/player/personalisation.py`.
2. **Updater signature**: `shrink_shot_distribution(prior: PlayerShotDistribution, *, carry_observations, lateral_observations, joint_observations, config) -> ShotDistributionUpdateResult`
   operating directly on `PlayerShotDistribution` (already a `statistics`
   type — no redundant raw-float parameter struct needed).
3. **Shrinkage formulas**: precision/pseudo-count-weighted convex
   combination of prior and weighted sample statistic, per parameter (see
   "Shrinkage math" below). Student-t scale <-> covariance conversion via
   the existing `nu/(nu-2)` factor (matches `implied_covariance_metres_sq`).
4. **Configuration**: `PersonalisationConfig` (statistics-side pseudo-counts/
   thresholds) + `MEASUREMENT_QUALITY_WEIGHTS` (player-side, since it needs
   `ShotMeasurementQuality`) — both explicit, versioned, provisional.
5. **Endpoint lateral vs intrinsic lateral — Decision A**: V1 treats
   `ShotRecord.lateral_offset_metres` (final resting position) as an
   acceptable, documented, replaceable approximation for
   `PlayerShotDistribution`'s lateral dimension. Carry-space parameters are
   never derived from endpoint data — only from genuinely observed
   `observed_carry_metres`. `final_downrange_metres` is not consumed by
   this updater at all.
6. **Measurement quality usage — Decision B**: explicit numeric weights by
   `ShotMeasurementQuality` (`MEASUREMENT_QUALITY_WEIGHTS`), not filtering,
   not ignore-for-now. `ShotMeasurementSource` remains metadata-only (not a
   second weighting axis) in V1.
7. **Partial observations**: per-dimension, per-record evidence selection
   (weight 0 excludes a dimension for that record without discarding the
   whole record); joint (correlation) evidence requires both carry and
   lateral usable for the same record, weighted by `min()` of the two leg
   weights.
8. **No ADR required.** No AGENTS.md §13 trigger is hit (no new dependency,
   no public API contract break, no unit/ownership/dependency-direction
   change, no deterministic-strategy-principle change). ADR 0006 is
   unaffected — the endpoint/intrinsic-lateral finding is an
   estimation-procedure limitation, documented in `docs/player-model.md` and
   the new module's docstring, not a change to `PlayerShotDistribution`'s
   contract.
9. **No NEEDS_DECISION conditions apply.**

### Task 1 — QA Engineer: test design

Write failing/pending tests (from acceptance criteria and the issue's
"Testing" section) in `tests/test_statistics_personalisation.py` (pure math)
and `tests/test_player_personalisation.py` (glue), before/alongside
implementation. Must cover at minimum:

- no observations → unchanged result, all outcomes `NO_EVIDENCE`
  (except dof, always `HELD_FIXED_BY_POLICY`)
- one useful observation → partial movement toward it, not full replacement
- increasing sample size → monotonically stronger movement toward the
  empirical value
- carry location/scale updated only from genuine `observed_carry_metres`
  evidence; absent `observed_carry_metres` never uses
  `final_downrange_metres` as a carry proxy
- signed lateral evidence accepted from `lateral_offset_metres`; left/right
  bias learning (including superseding an onboarding common-miss bias with
  sufficient contradicting evidence)
- 1-2 observations never collapse dispersion/correlation toward zero or the
  sample value
- sufficient observations can move dispersion materially
- correlation stays at prior when evidence is below the effective-count gate
- correlation updates (shrunk, not replaced) once evidence clears the gate
- degrees_of_freedom is always retained unchanged
- genuine severe-shot values remain usable (no outlier removal)
- `HIGH`/`MODERATE`/`LOW`/`UNKNOWN` quality weighting behaviour, including
  `UNKNOWN` contributing zero weight by default
- partial `ShotRecord`s (missing `observed_carry_metres`, or low-quality
  endpoint) — dimension-specific selection, no whole-record discarding, no
  fabricated values
- finite-value handling / rejection of non-finite inputs
- Student-t scale vs covariance conversion correctness (a test that would
  fail if scale were mistakenly treated as stddev)
- resulting `PlayerShotDistribution` always valid (finite, positive scales,
  correlation strictly in (-1,1), same `nu`, implied positive-definite
  scale matrix)
- deterministic repeated calls with identical inputs produce identical
  output
- architecture boundary: `caddai.statistics.personalisation` imports no
  `caddai.player`; both new files are covered by
  `tests/test_architecture_boundaries.py`'s `SUBSYSTEM_BOUNDARIES`

## Architect decision record (full text)

See the CaddAI Architect subagent's full response, summarized above. Key
formulas (also restated in module docstrings):

- `factor = nu / (nu - 2)`, unchanged from prior.
- Location (carry location, lateral bias): `posterior = (location_prior_pseudo_count * prior_value + n * sample_mean) / (location_prior_pseudo_count + n)`, `n = sum(weights)`.
- Scale (carry scale, lateral scale): convert to variance
  (`prior_variance = factor * prior_scale**2`), pool variances with
  `dispersion_prior_pseudo_count`, convert back
  (`posterior_scale = sqrt(posterior_variance / factor)`); gated by
  `dispersion_min_effective_observations`.
- Correlation: pool weighted sample Pearson correlation with
  `correlation_prior_pseudo_count`, hard-gated by
  `correlation_min_effective_observations` (below gate: prior unchanged).
- Degrees of freedom: always retained, never estimated.
- Config values are illustrative/provisional (e.g.
  `location_prior_pseudo_count=5.0`, `dispersion_prior_pseudo_count=30.0`,
  `dispersion_min_effective_observations=2.0`,
  `correlation_prior_pseudo_count=60.0`,
  `correlation_min_effective_observations=40.0`,
  `MEASUREMENT_QUALITY_WEIGHTS={HIGH: 1.0, MODERATE: 0.6, LOW: 0.25, UNKNOWN: 0.0}`) —
  not calibrated, replaceable without an ADR (same precedent as
  `population_prior_config.py`/`ONBOARDING_COMMON_MISS_BIAS_STRENGTH`).
